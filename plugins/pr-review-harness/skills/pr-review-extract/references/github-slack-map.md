# GitHub アカウント → Slack アカウント 変換表

配信する候補投稿で、指摘したレビューアーと元PRの Author を Slack でメンションするための対応表。
**投稿する文面を組むときはこの表を引く**（`../SKILL.md` の「配信プレビュー」）。

> **導入時にやること**: 下の「対応表」は記入例だけの空テンプレートです。自分のチームの行を
> 足してから使ってください。1行も無い状態でも動きます（全員が平文の `@login` で出るだけで、
> 通知が飛ばないので票が集まりにくくなります）。

## メンションはメンバーIDで書く

Slack に通知が飛ぶのは `<@U0123ABCDEF>` の形（メンバーID）だけ。
`@takkun` のように表示名を書いても**ただの文字列**になり、本人には何も届かない。
表示名は本人がいつでも変えられるうえ、休暇の告知（`taro（9/9休）`）を付ける人もいるので、
表示名を保存してはいけない。**恒久キーはメンバーIDのほう。**

## 自社DBに Slack ID があっても、この表を別に持つ理由

社内メンバーの Slack メンバーIDを自社DBに持っている組織は多い。それでもこの表を別に持つのは、
たいてい次の2つが揃わないため。

- **GitHub の login を持つカラムがない。** DBを正にするならカラム追加とバックフィルが要る
- **週次運用はクラウドの隔離セッションで動き、DBに触れない。** DBを正にすると定期実行から引けない

つまりDB側は「社内メンバー → Slack ID」で、足りないのは GitHub login との対応だけ。
将来DBに GitHub の login が入ったとしても、クラウド実行から引けない制約は残る。

## 対応表

`GitHub login` は API の `user.login`（PRの Author）と `comments[].user.login`（指摘したレビューアー）。
`照合根拠` は、その行をどう突き合わせたか。**メールアドレスは残さない**（リポジトリに個人の
メールを増やさないため）。

| GitHub login | Slack メンバーID | 照合根拠 |
|---|---|---|
| `<記入例: octocat>` | `<記入例: U0123ABCDEF>` | 社内メール一致 |
| `<記入例: hubot>` | `<記入例: U0456GHIJKL>` | GitHubプロフィールの氏名一致 |

**未対応**（メンションせず GitHub login のまま出す）: なし。

bot（`dependabot[bot]` 等）はそもそも抽出対象外なので、この表に載せない。

## 表に無い login が出てきたとき

**推測でメンションしない。** 別人に通知が飛ぶと、通知を切られて投票が集まらなくなる。
表に無ければ `@<login>` の平文（メンションにならない）で出し、その login を上の未対応表に足す。

行を起こすときの手順。**メールが一致したときだけ確定扱いにする。**

1. **社内メールを引く** — `gh api "repos/<owner>/<repo>/commits?author=<login>&per_page=5"` の
   `commit.author.email` を見る。`<数字>+<login>@users.noreply.github.com` しか出ない人もいる
   （GitHubのメール非公開設定）。その場合は 3 へ
2. **メールで Slack を引く** — Slack のユーザー検索にそのメールを渡す。1件に絞れたらそれで確定
3. **氏名で引く** — `gh api "users/<login>"` の `name` で Slack のユーザー検索を叩く。
   ここで得た候補は同姓同名がありうるので、**1件に絞れないなら確定しない**（未対応に入れる）
4. 確定した行を対応表に追記し、`照合根拠` にどの手段で当てたかを書く

同姓同名が実在する組織では、その行に「同名がもう1人いる」と書き残しておくと、次に誰かが
この表を触るときに表示名まで確かめる判断ができる。

## メンションが通知にならない場合

- **チャンネルに居ない人をメンションすると**、Slack は投稿者だけに見えるかたちで招待を促す。
  投稿自体は成立するが本人には届かないので、配信チャンネルには参加してもらう
- **退職者のIDはメンションしても届かない。** 表から消さず、未対応表へ移して理由を書く
  （消すと次の実行が手順1からやり直して、また同じIDに当ててしまう）
